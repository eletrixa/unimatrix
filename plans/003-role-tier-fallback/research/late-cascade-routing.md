# Late research — cascade / cheapest-capable routing (replacement agent, 2026-07-24)

The workflow's original cascade-routing agent died on structured-output retries; this replacement
ran as a plain-text sonnet agent. Findings validated the PRD's O2 answer (pre-generation routing
beats cascade on 4/5 benchmarks — arXiv 2605.06350) and drove the FR-R14 routing rules.

SUMMARY: FrugalGPT (2023) established the LLM cascade — query models sequentially, stop when a reliability check passes — cutting cost up to 98% at matched GPT-4 quality; RouteLLM (2024, ICLR 2025) reframed routing as upfront binary classification (win-prediction from Chatbot Arena preference data) trained before generation, hitting 85%/45%/35% cost cuts on MT-Bench/MMLU/GSM8K at 95% of GPT-4 quality. 2025-2026 successors (AutoMix, UCCI, "Cluster, Route, Escalate", "Is Escalation Worth It?") split into two camps: cascade (try-cheap-then-escalate, gated on post-hoc confidence/uncertainty signals) versus upfront pre-generation routing (gated on query features before any generation happens). The most load-bearing 2026 finding: cascades structurally pay the cheap model's inference cost before deciding to escalate, so whenever cheap pre-generation signals (embeddings, keyword/structure heuristics, a tiny classifier) actually predict difficulty, upfront routing beats cascading on both cost and quality — cascading only wins when pre-generation signals are near-uninformative (e.g., open trivia QA). Self-reported/verbalized LLM confidence is empirically unreliable (miscalibrated, clusters on round numbers, swayed by suggestibility) across multiple 2025-2026 surveys, so production systems use signals that don't ask the model to grade itself: token-level log-prob margins/negentropy, semantic-entropy probes, learned confidence probes on hidden states, or — for code/agentic tasks — actual execution feedback (unit test pass/fail, type-check, build result) as the escalation trigger. Commercial routers (RouteLLM, Not Diamond, Martian, Unify) report 40-85% cost reduction at 95%+ quality retention in production.

KEY POINTS:
- FrugalGPT (arXiv 2305.05176, Chen et al. 2023): sequential ranked-model cascade, stop at first "reliable enough" response; 98% cost reduction at matched GPT-4 accuracy, or +4% accuracy over GPT-4 at equal cost.
- RouteLLM (arXiv 2406.18665, LMSYS, ICLR 2025): binary win-predictor from Chatbot Arena preference data, routes upfront (no cheap-model call wasted). 85% cost cut on MT-Bench, 45% MMLU, 35% GSM8K vs always-GPT-4, at 95% of GPT-4 quality; beat commercial routers by >40% cost-efficiency in independent comparisons.
- AutoMix: few-shot self-verification as NLI/entailment fed into a POMDP router rather than trusting raw self-verification; >50% compute reduction at comparable quality vs FrugalGPT/HybridLLM.
- "Is Escalation Worth It?" (arXiv 2605.06350, 2026): decision-theoretic cascade optimization; best signal was mean token negentropy (free, no extra model call); pairwise two-model cascades hit 79.5% cost reduction at 90% of ceiling quality; multi-stage chains gave negligible extra gain over the best two-model cascade.
- Same paper's central architecture finding: a lightweight pre-generation embedding router beat cascading on 4 of 5 benchmarks — structurally, because cascades always pay the discarded cheap run; cascading only stayed competitive where pre-generation signal was near-random (AUROC ≈ 0.49 on TriviaQA).
- UCCI (arXiv 2605.18796, 2026): token-margin aggregation + isotonic regression → calibrated error probabilities usable directly as a cost-constrained escalation threshold.
- "Cluster, Route, Escalate" (arXiv 2606.27457, 2026): Stage 1 clusters queries and pre-assigns each cluster to its cheapest adequate model; Stage 2 live quality-estimation cascade escalates only low-quality outputs. unimatrix's C1-C4 labels ≈ Stage 1.
- Self-reported/verbalized confidence is empirically unreliable: round-number anchoring, overconfidence on low-knowledge claims, degrading calibration in low-resource domains — 2025-2026 surveys converge: don't trust the model grading itself.
- What works instead: (1) token-level log-prob signals (min-token-prob, negentropy, top-2 margin) — free; (2) semantic entropy probes (arXiv 2406.15927; Farquhar et al., Nature 2024) — single-pass approximations; (3) execution-based verification for code/agentic tasks — tests/type-check/build as ground truth; (4) a separate small verifier model, explicitly NOT same model/family as the executor.
- Heuristic tiers vs learned routers: heuristics are cheap/auditable/zero-training but boundary-brittle; learned routers win once real outcome data exists. Practical systems converge on heuristic tiers first, learned router later.
- Coding-agent framing (arXiv 2606.22902 "Agent-as-a-Router"): "escalate only when the cheap tier fails its own verification" — cascade-with-execution-feedback, because code has a near-ground-truth pass/fail signal.
- Threshold-setting rule across every source: calibrate the escalation threshold from held-out outcome data mapping the cheap signal to actual downstream failure rate — never intuition.

RECOMMENDATIONS for unimatrix:
1. Treat C1-C4 as upfront/pre-generation routing (RouteLLM-style), not a cascade gate; cascade only where the complexity label itself is historically mispredicted.
2. Never add "how confident are you" prompting to any lane; use exit codes, `bats tests/`, shellcheck, cross-model review — card success/failure is the escalation signal.
3. Feed speedwars per-lane outcome rows into a periodic (offline) recalibration of the C-label→lane mapping — speedwars already IS the outcome dataset the calibration rule demands.
4. Log which signal triggered each escalation (label-mismatch vs test failure vs reviewer rejection) in run evidence — this becomes the training signal for any future learned router and audits threshold tightness.
5. Any lane-internal cascade (haiku→sonnet within a card) gates on free post-hoc signals (exit status, tests, lint, output validity), never a same-family judge call.
6. Static heuristic tiers are right at current volume; revisit a learned router only once speedwars has enough rows to train a real win-predictor.

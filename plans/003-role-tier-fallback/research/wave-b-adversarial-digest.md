## steelman-for
Steelman FOR a static role-tier hierarchy: Fable at top as Planner/Orchestrator/Auditor/Reviewer; Kimi plus Codex as high-level review and verify; Grok plus GLM as bulk execution; claude haiku to sonnet to opus as a cheapest-capable escalation ladder. Static beats learned routing at unimatrix's scale because the routing literature agrees static rules capture about 80 percent of the value in a few dozen lines while learned routers only pay off at traffic and labeled-data volumes this single-operator tool has not reached, and a learned router demands perpetual re-calibration against outcome data the repo lacks. Static also preserves the zero-daemon, zero-MCP, greppable-config constraints and spec 04's ratified no-per-branch-auto-routing non-goal, and matches the PLAN/EXEC/REVIEW stage split swarm.conf already has. The lane assignments each fall out of documented evidence: Fable/Opus concentrates intelligence where leverage is highest and token volume lowest; Codex is the most-trusted reviewer in unimatrix's own run-reviews and Kimi its shipped cross-family partner; Grok and GLM are cheap and fast but each has a high-level weakness that disqualifies review while fitting tightly-spec'd bulk exec. Cost math is decisive: Cursor measured Opus-planner plus cheap-worker at 1339 dollars vs 10565 all-frontier at equal quality, and unimatrix's own ledger shows the claude lane alone booked 98.92 real dollars across 59 cards vs grok's 8.55 notional over 38, proving bulk-on-claude is the leak the static rule plugs. Static's one real risk, mis-routing a hard card to a cheap lane, is already caught by the artifact/diff gate and judge-not-executor review that a learned router would need anyway and cannot replace. Every static assignment already has, or trivially gains via a REVIEW_CHAIN reusing the shipped chain primitive, a fallback, so a wrong-but-recoverable static route self-heals. Static plus fallback chains is strictly simpler than, and empirically as good as, a learned router that would also need fallback chains.
KEY POINTS:
- WHY STATIC BEATS LEARNED AT THIS SCALE: LiteLLM docs, RouteLLM, and the 2026 decision-theoretic cascade paper all converge that static keyword/length/metadata rules capture about 80 percent of the value in a few dozen lines, and a trained classifier or embedding router only earns its added latency and infra once traffic and labeled-outcome volume are high. unimatrix has 187 done rows across 4 lanes and one 0.028-dollar kimi smoke ping, far below the threshold that makes a learned router pay. Static is evidence-prescribed here, not a budget compromise.
- WHY STATIC, calibration burden: RouteLLM needs preference-labeled data and UCCI needs isotonic recalibration (ECE 0.12 to 0.03) before its scores can be trusted, and every source warns a drifting verifier can silently escalate everything, meaning routing accuracy must be re-monitored against real outcomes forever. A static map you can read and grep beats a black-box scorer you cannot yet validate; the same speedwars ledger you would use to calibrate a router is what you use to hand-tune the static assignments at plan time.
- WHY STATIC, constraint fit: a learned router is a stateful model-scoring component that violates unimatrix's zero-daemon, zero-MCP, no-new-dependency boundary and makes what-will-actually-run un-greppable. A static map is one KEY=VALUE line printable via slash-swarm-config, and it honors spec 04's ratified non-goal that a human or Fable picks lanes and config only sets defaults, so it ships without reopening a closed decision.
- WHY STATIC, it already exists in the design: the strongest cross-source finding (Anthropic Opus-lead/Sonnet-worker split, Cursor economics, and the source-agnostic idea inside even weak Anthropic-cascade content) is to treat each pipeline stage plan/exec/review as its own routing decision, claimed 30-50 percent workflow savings. swarm.conf's PLAN, EXEC_CHAIN, and REVIEW roles already are that per-stage static split, so a static role-tier map extends the existing shape rather than bolting on a foreign per-branch router.
- WHY STATIC, ROI: multi-agent coordination overhead is real and measured at 3-10x tokens and about 950ms handoff latency per pipeline, and a learned router adds its own inference hop per card. Static pre-assignment adds zero hops and zero routing inference because Fable, the never-spawned live session, picks the lane at plan time at roughly zero marginal cost. Small accuracy gain versus large added spend, latency, and opacity favors static.
- FABLE AT TOP IS RIGHT: Anthropic's own multi-agent system pins planning and adjudication to the strongest model (Opus-4 lead plans and saves the plan before spawning Sonnet-4 workers, measured plus 90.2 percent quality over single-agent), and Cursor data shows planners consume only 10-31 percent of tokens yet decide the few moments that require frontier intelligence. Planning-failure-propagation means a weak plan dooms downstream work regardless of executor quality, so intelligence belongs concentrated at the top. Fable is both the strongest model and the never-spawned session, making it the highest-leverage, lowest-cost placement.
- KIMI PLUS CODEX AS HIGH-LEVEL REVIEW IS RIGHT: Codex is the most-trusted reviewer in unimatrix's own evidence, scored 5,4,5,4 across four runs and credited with catching bugs no other lane found (ratified-SQL backfill bug, NULL-queue defect, path-traversal CRITs), with the largest non-Claude context/output ceiling at 400K/128K for big diffs. Kimi K2.7 is top-end competitive, beating Opus 4.8 on MCPMark Verified 81.1 vs 76.4, and is the shipped FR-15 codex partner. Pairing them gives review a cross-family fallback, satisfying the judge-bias rule that a smarter judge is not a fairer judge; only different-family separation fixes the 75-84 percent self-family win-rate bias.
- GROK PLUS GLM AS BULK EXEC IS RIGHT: both are strong, cheap bulk executors at 5-12x cheaper per token than Opus, but each has a high-level weakness that disqualifies review while leaving exec untouched. Grok explains its reasoning less than competitors, which is fatal for legible critique, and GLM is weakest at open-ended multi-step planning and degrades in instruction fidelity above about 64K context. Review and spec-critique are exactly open-ended, legibility-demanding work, whereas tightly-spec'd codegen cards are not, so the static assignment matches each lane to the work shape its profile fits.
- GROK WRITE-VS-REVIEW SPLIT STRENGTHENS THE STATIC TIER: agentbench-008 scored grok 2 on write and 4 on review in the same run, and the live ledger shows grok with 25 retry rows of false-done churn against 38 dones. A static tier encodes that nuance as config (grok write off, review-eligible), whereas a learned router must re-discover a per-lane, per-role trust asymmetry from sparse data. Static config captures human-known lane facts a scorer cannot yet learn.
- CLAUDE HAIKU-SONNET-OPUS LADDER IS RIGHT AND FREE: it is purely an EXEC_CHAIN ordering convention needing zero new code because MAX_LANE_RETRIES already walks a chain. Opus 4.8 is the best-evidenced ceiling, the only model in the set with a vendor-reported claim of being about 4x less likely to let its own defects pass unmentioned, the exact false-done failure mode unimatrix tracks, so reserving it as the top rung rather than a default is correct given it is priciest at 5/25 dollars per million.
- COST MATH, the thesis in one number: Cursor's swarm-economics study booked Opus-planner plus cheap-worker at 1339 dollars total vs 10565 for an all-frontier model doing both roles, at comparable final quality, about 8x cheaper. Workers used 69-90 percent of tokens but only about a third of cost because planner tokens are far pricier per token. Concentrate the expensive model on the hard decisions and push bulk to cheap lanes is the entire static-tier design.
- COST MATH, unimatrix's own ledger: the claude lane alone booked 98.9216 real Anthropic-priced dollars across 59 done cards, vs grok 8.55 notional over 38 and GLM pool-metered prompts over 33, while codex reports 0 as token-only. The most expensive aggregate lane is claude, so the static rule of bulk to grok/glm/codex and reserve claude/opus as the ladder ceiling is literally the cost-minimizing assignment on this repo's real spend.
- COST MATH, per-token spread: a wrong everything-on-Opus default is 5-12x too expensive since Opus is 5/25 per million vs Kimi 0.95/4 (OpenRouter 0.72/3.50), GLM 1.40/4.40 (OpenRouter 0.56/1.76), Grok 2/6, Codex 1.75/14, Haiku 1/5. A static tier that pins bulk to the sub-1.5-dollar-input lanes and reserves the 5-dollar lane for escalation captures that whole spread by construction, every run, with no per-card decision cost.
- COST MATH, no double-pay: the 2026 decision-theoretic paper found a pre-generation router beats a run-cheap-then-escalate cascade on 4 of 5 benchmarks precisely because cascading always pays the cost of the cheap run even when discarded. A static tier is a pre-generation route since Fable assigns the lane at plan time, so the cheap lane runs first by config and the expensive lane runs only on genuine escalation, never paying twice.
- ESCALATION STAYS SHALLOW: cascade research agrees 2-stage captures nearly all value, with deeper chains beating the best pairwise choice by only 0.014 normalized gain. So the static ladder needs no deep per-card tree; cheap to one qualified escalation target per card-type captures almost all benefit and bounds worst-case escalation spend, making static both simpler and near-optimal.
- STATIC'S ONE RISK IS ALREADY GUARDED AND A ROUTER CANNOT REPLACE THE GUARD: the failure mode is mis-routing a hard card to a cheap lane that returns confidently-wrong output, but learned routers also mis-classify hard-as-easy and raw confidence signals are miscalibrated, so a router is not the net either. The real safety net is unimatrix's independent artifact/diff gate plus judge-not-executor review, needed regardless of routing. Static adds no un-guarded risk and removes the router as a second component that can silently drift.
- STATIC MEETS EVERY-ROLE-NEEDS-A-FALLBACK MORE SIMPLY: the requirement is met by config lines reusing shipped primitives, the EXEC_CHAIN chain_current/advance/reset tracker, the VERIFY_MAP codex-kimi pair, and a proposed REVIEW_CHAIN rewiring the same chain mechanism onto the judge role. A learned router would also need every one of these chains on top of itself, so static plus fallback chains is strictly a subset of learned-router plus fallback chains, same resilience with less machinery.
- SCOPE DISCIPLINE STRENGTHENS THE CASE: PLAN and ORCHESTRATOR stay hard-pinned to Fable with no auto-fallback, declared an explicit non-goal (Fable outage equals manual resume) because auto-resuming a second orchestrator crosses spec 03's ratified no-unattended-driver-in-v1 boundary. A static hierarchy accommodates this cleanly since the top role simply is not auto-routed, whereas a universal-router framing would falsely imply the live session should be auto-substituted, which is architecturally un-buildable today.

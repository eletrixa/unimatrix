| Candidate | Named precedent | The lesson we import |
|---|---|---|
| C1 (local SQLite) | **atuin** (shell history: CLI tool, local SQLite, optional sync server added later) | The exact evolution path C1 claims — local file first, network sync only when a consumer exists — shipped and liked at large scale |
| C1 | **simonw/git-history** | Watermarked, idempotent, rebuild-safe JSONL/CSV→SQLite import is a solved shape; correction folding via `--skip/--start-after` precedent |
| C1 | **Datasette** ecosystem | A SQLite store without an inspection tool goes unread — C1 must ship/document its reader (`sqlite3` one-liners or Datasette pointer), or it inherits pre-mortem #16 |
| C1 (caution) | **ultrathink.art incident** (HN 47637353) | WAL does not save you from multi-writer on shared volumes — single-writer importer discipline is the property, not the journal mode |
| C2 (Postgres) | **Brain `ops.cockpit_run_telemetry`** (in-house) | Stable-columns + jsonb payload + owner-pool-only access — the schema and access shape C2 would copy; also proof the eventual consumer side is Postgres |
| C2 | "Just use Postgres" shops (advocacy essays) | Real, but evidence-thin at single-operator scale — no regret reports because almost nobody that small runs one; treat as weak signal both ways |
| C3 (no-DB) | **DuckDB `read_ndjson`** practice | Ad-hoc SQL over compressed JSONL with zero import step exists today; format-instability confines DuckDB to query-engine role |
| C3 | Solo-operator static reporting (GoAccess-class) | Static reports survive years when they're regenerated by the same command that produces the data; they rot when a second toolchain owns them — C3's report must be one CLI verb, not a separate site |
| Plugin | **agnes marketplace** (this machine) + official plugin docs | Directory-sourced marketplace works today; plugins run from a cache copy → generated-commands build step + `doctor --plugin` drift table are mandatory, not nice-to-have |

## Overview

A third operating profile for unimatrix that bundles three modes under one family — the captain's ready room, where decisions get made (Star Trek naming; the ready room is where the captain retires to weigh evidence and commit). The three modes:

- **readyroom:research** — a deep-research sweep. glm + grok fan out across the question, grok is the web-capable lane pulling live evidence, and the tricorder card spot-checks sampled citations against the live web.
- **readyroom:decision** — a domain decision. Two independent 4-candidate weighted matrices are scored by judge-seat cards, then an adversarial court (scoring-refute + triangulation) stress-tests the winner before it commits.
- **readyroom:ceo** — a CEO decision. M1/M2 scoring against a frozen rubric, judge-seat cards resolve the call, and the deliverable is a two-pager.

The **mode pipelines** (the wave/card choreography for each mode — matrix construction, the adversarial court, M1/M2 scoring, the two-pager assembly) are **owned by the `rfg-` skills in the refactor lead repo**, not by unimatrix. Unimatrix owns exactly three things for readyroom: the **profile conf** (`profiles/readyroom.conf`), **one engine knob** (`GROK_TOOLS`, the read-only grok tool allowlist), and the **launch gates** (doctor preflight + the anthropic-share cost target). Like thrifty, this is configuration riding the spec 04 precedence chain — `swarm.conf` is never edited; `CONF=profiles/readyroom.conf` selects the profile.

## Goals

1. **Deliver research/decision outcomes at controlled Anthropic cost:** opus quality where it changes the answer (the judge seats), codex everywhere else (the per-done-card verify wave). Opus mode target ≤50% of priced cost (expect 30-45%); codex economy mode <10%.
2. **A web-capable lane for evidence:** grok is the web lane — `web_search` + `web_fetch` fire headless under the read-only allowlist, so research cards pull live evidence and the tricorder card fact-checks it.
3. **One judge switch spanning every judge seat:** a single `READYROOM_JUDGE` env var (opus default | codex) flips the review seat, the review class, the verify map, and the model the judge-seat cards are pinned to — economy mode is one export away.
4. **Zero engine change except the one knob the web posture needs:** the profile is pure conf; the only engine touch is `GROK_TOOLS`, and its default argv is byte-identical to the pre-knob argv, so nothing else moves.

Captured as FR-7 (out-of-scope row) rather than duplicated here — gemini lane revival, the per-card `.allow` sidecar, kimi, and the `rfg-` skill pipelines themselves all live there.

## Design

**Profile selection (sibling to thrifty).** Readyroom is selected the same way thrifty is: `CONF=profiles/readyroom.conf` feeds the existing `conf_load` precedence chain (spec 04 FR-1: already-set env > conffile > baked default). `swarm.conf` is never edited for a readyroom run — the operator selects the profile via `CONF`, not by rewriting roles. The profile file ships `PLAN=fable` / `ORCHESTRATOR=fable` deliberately: a seated non-fable PLAN lane is banned from *all* judging by `_judge_ok` (spec 10), so fable must hold the plan/orchestrator seats even though the actual mode choreography is driven by the rfg skills' delegated cards.

**`READYROOM_JUDGE` — one switch, two consumers, source-time read.** Because `conf_load` *sources* the profile, the `READYROOM_JUDGE` conditional executes at load time and rewrites `REVIEW` / `CLASS_REVIEW` / `VERIFY_MAP` before conf_load's env re-overlay runs — so an env-set `REVIEW` or `VERIFY_MAP` still wins (the escape hatch). `READYROOM_JUDGE` itself is deliberately **not** a `CONF_KEY`: it is a source-time input to the conditional, read straight from the environment, so it must be `export`ed in the launch env (unset → the `:-opus` default applies). The second consumer is the `.lane` the rfg skills stamp on each judge-seat card at seeding: opus mode pins matrix scorers, M1/M2 scoring, scoring-refute, and triangulation to `claude:opus`; codex mode pins them to `codex:default`. The cost control is the split between *pinned judge seats* (opus, few) and the *bulk verify wave* (codex, one card per done card): the bulk glm/grok executors never draw an opus verify. Opus does enter the verify wave through exactly one pair — `codex:claude` resolves the judge of codex-*executed* cards to opus via `_verify_default_model` — and that spillover rung is rare by construction (codex is rung 3 of the exec chain). In opus mode the opus judge-seat output is itself cross-checked by codex through the `claude:codex` `VERIFY_MAP` pair rather than by a second opus pass.

**`GROK_TOOLS` — the one engine knob.** The only engine change readyroom needs is making the grok read-only tool allowlist configurable. `conf_load` defaults `GROK_TOOLS` to `read_file,grep,list_dir` with `:=` — empty is collapsed back to that default because an empty allowlist means "allow nothing", which is never what a read-only research card wants. The grok read-only branch of `lane_cmd` consumes it as `--tools "${GROK_TOOLS:-read_file,grep,list_dir}"`; the readyroom profile sets `GROK_TOOLS=read_file,grep,list_dir,web_search,web_fetch` to make read-only grok cards (and the tricorder) web-capable. With `GROK_TOOLS` unset the branch emits exactly the bytes it emitted before the knob existed — the default-argv contract. The write branch is unchanged: grok write cards pass no `--tools` at all and carry the full default toolset (web included) via `--allow Write/Edit/Create`.

**Web posture + tricorder.** grok is the only seated lane with live web, so it is the research/evidence lane. gemini (the other historically-web lane) is demoted to optional and left out of the readyroom classes. The tricorder card class is the integrity check on the research sweep: one read-only grok card per run samples N citations from the evidence files and re-resolves them against the live web, catching fabricated or stale URLs before a judge seat reasons over them.

**Cost measurement.** The existing anthropic-share footer (spec 22 / spec 08) is the single measurement surface — no new report. Readyroom runs use `rr-<slug>` run labels so `unimatrix report --run rr-<slug>` isolates the run's claude-lane share; opus mode should land at ≤50% (the pinned judge seats are expensive but few), codex economy mode at <10%.

## Boundaries

- **Always**: run the `DOCTOR_LANES="glm grok codex claude" doctor --live` gate before any readyroom launch. Select the profile via `CONF` — never edit `swarm.conf` for a readyroom run. Keep the default `GROK_TOOLS` argv byte-identical to pre-knob (the knob must be a no-op when unset). Log every card attempt's spend in the run-evidence ledger.
- **Ask first**: adding a lane beyond the six-lane freeze (spec 10 / CLAUDE.md); changing the pinned `--json` report contract; reviving gemini as a seated lane.
- **Never**: seat a non-fable PLAN lane (`_judge_ok` bans it from all judging). Edit `swarm.conf` for a readyroom run. Grant Bash to caged workers via a per-card `.allow` sidecar (a containment change, not a profile knob — spec 14). Spend on a card lane without ledgering it.

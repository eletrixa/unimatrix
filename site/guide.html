Second opinion, or grinding loop?

This page is for typing into Claude Code, not a terminal. /swarm gets you a second opinion from four genuinely different AIs, once. /swarm-loop keeps grinding until your criteria actually pass, checked by a judge that never trusts the model doing the work.

Escalation ladder

Start cheap. Never start at max.

Three rungs. Climb one at a time, and only when the question earns it.

Just ask Claude
one turn, one model — right by default, for almost everything
/swarm
one round, four models — a second opinion, once
/swarm-loop
many judged rounds — until a criterion holds, not until someone claims done

Most questions never need to leave the bottom rung.

Before you climb

Is a correct answer worth 3–15× the tokens of asking once? If not, just ask Claude.

A swarm branch runs four models instead of one, then spends more tokens again cross-checking them. That multiplier is real money and real wait time. Pay it for decisions that are expensive to get wrong — not for things you could answer yourself in the time it takes to type the prompt.

When not to swarm

A swarm only helps when the question actually splits into independent pieces. Some things don't.

One indivisible reasoning chain

A problem that has to be worked through as a single unbroken train of thought has nothing independent to fan out. Splitting it across four models just loses the thread four times.

Tightly-coupled coding

Code where every file depends on a decision made in the file next to it. Four models editing in parallel means four incompatible guesses about that decision, not four options to pick from.

Workers that must agree on shared design mid-flight

Branches don't talk to each other while they're running — they can't negotiate an API shape or a schema as they go. Settle the shared design yourself first, then swarm the parts that don't need to negotiate.

Prompts by job

Type these into Claude Code as-is, or swap in your own question — the shape is what matters. Grouped by what each mode is actually for.

/swarm — second opinion, once

One round: plan, fan out to four models, cross-verify, synthesize. Use it when being wrong is expensive, or when you want disagreement surfaced instead of hidden.

Risky, hard-to-reverse decision — worth the multiplier.

claude code
/swarm "Should I migrate this project's session storage from Redis to Postgres? Give the top 3 risks and a go/no-go recommendation."

Security cross-check — four lineages beat one.

claude code
/swarm "Review the auth middleware change in the latest commit — does it introduce any bypass or privilege-escalation path?"

Breadth-first research — the validated sweet spot.

claude code
/swarm "Compare Cloudflare Workers, Deno Deploy, and Fly.io for a low-traffic dashboard: cold starts, pricing at ~100 req/day, WebSocket support."

Forcing genuine disagreement — different models, different priors.

claude code
/swarm "SQLite vs plain JSONL files for a single-operator run ledger under 10k records — pick one and defend it."

Verification — dissent surfaced, not smoothed over.

claude code
/swarm "Is this error message accurate and is the fix in PR #12 the root cause? Cite the exact lines."

/swarm-loop — keep grinding until it's actually true

Many rounds: write the success criteria once, then exec, judge, repeat. Stops when the criteria genuinely hold — or loudly, when they can't.

Writing your own --until: it has to be something a different model can verify by running a command or reading an artifact — a test suite's exit code, an HTTP status, a file that exists. Never "until it looks good." That's not a criterion, it's a vibe, and a judge can't verify a vibe.

Criteria = a command's exit code — not an opinion.

claude code
/swarm-loop "Make the test suite pass after the bus refactor" --until "bats tests/ exits 0 with zero skipped tests"

Criteria that defeat premature "done" — a flaky fix has to prove itself repeatedly.

claude code
/swarm-loop "Fix the flaky claim test" --until "20 consecutive runs of tests/bus-claim.bats all pass"

Criteria checkable from outside the executor — the doer can't grade its own homework.

claude code
/swarm-loop "Add llms.txt to the site" --until "curl -s https://unimatrix.asajj.cz/llms.txt returns HTTP 200 with Content-Type text/plain"

Reading the results

A swarm doesn't hand you four separate transcripts to reconcile yourself. Here's what actually shows up.

Synthesis

Lands at the bottom of this chat, after every branch has reported in. That's your answer — no digging through worker output required.

Dissent, shown explicitly

If models disagree, you see both positions, not a smoothed-over consensus. A 3-1 split is information, not noise — it's usually the most useful part of the answer.

Cost recap

Every run ends with what it actually spent, per model. You know the price of that second opinion before you ask for another one.

Watching it run

The moment a swarm starts, a live cockpit opens automatically in your browser — Ground Control starts the small local server behind it, you don't run anything yourself. It shows which model is doing what, live, and the running cost.

If you're a terminal person, the same run is also watchable read-only from a tmux session:

bash
tmux -L swarm attach -r -t mon
